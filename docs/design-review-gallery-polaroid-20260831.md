# 设计评审：图鉴「香水」页改版（拍立得浏览 + 日记式详情）

日期：2026-08-31
范围：`src/pages/gallery/gallery.vue`
目标：降低小程序的「AI 感」
评审透镜：`frontend-design` skill（反模式清单：模板化版面、通用字体、可预测布局）

---

## 一、诊断：AI 感到底在哪

**结论：不在文案，在版面气质。**

11 款香的文案（hook + 古先生说）本身是有性格的第一人称写作，例如
「白衬衫上的茶香，穿了一整天还舍不得洗」「一个人在河边坐着，什么都没想，只是闻着」。
这是项目里最不像 AI 的部分，**不应改动**。

AI 感的来源是「商品列表页」这一版式本身：
`左侧缩略图 + 右侧标题/副标题 + 三条灰底进度条`
—— 这是所有 AI 生成 app 的默认长相（电商货架脸），与「古先生的调香日记」的调性相冲突。
拍立得的建议方向是对的：**把「逛」从「挑货」变成「翻相册」**。

## 二、改动内容

### 浏览层：竖排商品列表 → 拍立得卡片组

| 项 | 改前 | 改后 |
|---|---|---|
| 容器 | 竖向 `scroll-view` 列表 | `swiper` 横向卡片组（circular + 前后露边） |
| 卡片 | 左图右文 + 3 条灰底进度条 | 白框相纸 + 胶带 + 照片 + 手写感短句 |
| 香调数据 | 卡片上直接显示 3 条进度条 | 移出卡片，只留在详情里 |
| 指示 | 无 | 圆点指示器 |

手写感采用**斜体近似**（用户决策）：`楷体/衬线 + font-style: italic`，
不引入字体文件 —— 省包体、免 `wx.loadFontFace` 的域名白名单手续。

### 详情层：规格表 → 日记页

| 项 | 改前 | 改后 |
|---|---|---|
| 首屏顺序 | 大图→标题→香气结构进度条→雷达→古先生说 | 贴图照片→标题→**古先生说**→（折叠）香气成分 |
| 香气结构 | 8~11 条灰底进度条，全部同一个绿 | 1 条堆叠色带（各香调本色）+ 图例 |
| 六维切换 | 原生 `<switch>` | 两枚文字 pill |
| 参数位置 | 首屏直给 | 收进「查看香气成分」折叠区 |

## 三、评审发现并已修的问题

### P1 · 拍立得漏掉了品牌（信息回退）

改版时把 `p.brand` 弄丢了 —— 原列表卡有「爱马仕 · 2005」，改后只剩香名和年份。
对香水图鉴而言品牌是有信息量的（娇兰 / 芦丹氏 / 爱马仕各有性格）。
**已修**：卡片底部改为两行 —— 香名 + `品牌 · 年份`，右侧 `No.N`。
为容纳第二行，照片高度 470rpx → 440rpx。

### P1 · 色带相邻色块无法区分

`ACCORD_COLORS` 里琥珀 `#c08a3e`、木质 `#8a6a3b`、香草 `#d2b48c`、烟草 `#6b4a2f`
同属棕调，堆叠后挨在一起分不出边界。
**已修**：相邻色块间压 1rpx 白线（`.rib-i + .rib-i`）。

> 分隔线只能取 1rpx，不能更粗：实测最小非零占比仅 **1%**（大吉岭茶），
> 约 7rpx 宽，2rpx 的分隔线会把细色块吃掉。

### P2 · 过期注释

`.deck` 高度注释在调整照片高度后失效。**已重算并更新**，并写明
「改照片高度或底部行数时这里必须跟着重算」。

## 四、评审发现的重要工具缺陷（已修）

### `audit-card-layout.mjs` 完全不跟踪 canvas 变换

mock ctx 里 `translate() / rotate() / scale()` **全是空函数**，
导致任何在变换之后绘制的元素都被记在**局部坐标**上。

表现：封存卡称号徽章被持续误报为 `越界 x=-46`（8 个场景全中）。
实际它是 `ctx.translate(bcx, 58)` + `rotate(-8°)` 后在局部 `(0,1)` 绘制的，
真实位置是 `x=74..166`，并未越界。

危害不止于误报 —— 更严重的是**会漏掉真实重叠**：
被变换的元素在日志里坐标接近原点，离它们真实所在的位置很远，
与别的元素算不出交集，真重叠就这样静默溜过去了。

**已修**：补上 2D 仿射矩阵（`matMul` / `matPoint` / `matRect`），
矩形与文字取四角投影后的包围盒；`save/restore` 连带存取矩阵且做拷贝
（直接 `push({...state})` 会让矩阵数组被共享引用，改动会泄漏回去）。

修复后：称号徽章坐标由 `-46` 修正为 `74..166`，8 个场景全部转绿，
**封存卡确认无越界问题**，此前是虚惊。

## 五、新增工具：`scripts/audit-selectors.mjs`

交叉校验模板用到的 class 与 `<style>` 里定义的 class，专治改版后的静默死代码。

实测两个方向都会误报，**因此只给提醒、不设门禁（exit 0）**，已知两类合法情况：

- **JS 钩子类名**：`CoachMask` 的 `.coach-annot` 只用于 `createSelectorQuery` 量高度，本就不该有样式；
- **纯布局容器**：`community` 的 `.menu-text` 只包住 `.menu-title` / `.menu-sub`，靠继承即可。

已核实二者都不是 bug，故未改动。

脚本本身踩过的三个坑（都已在代码注释里写明）：

1. 模板提取必须**贪婪**匹配到最后一个 `</template>`，
   非贪婪会停在内层 `<template v-if>` 的闭合标签上，只扫半个模板；
2. `:class="{ active: tab === 'perfumes' }"` 不能按空格拆整个表达式，
   也不能把所有带引号的串都当类名 —— `'perfumes'` 是比较值，只取冒号左边的键；
3. 样式块要先剥注释，否则注释里的文件名（`lab.vue`）会被当成 `.vue` 类。

## 七、遗留问题与建议

1. **香料的「香调贡献」仍是灰底进度条**，与香水的色带不一致。
   未改的原因：实测 104 种香料里有 3 种（柠檬 0.950、合成麝香 0.950、海水 0.920）
   accords 不求和为 1，堆叠色带会出现空隙。若要统一，需先归一化数据。
   （香水侧则已验证 11 款全部精确求和 100，色带安全。）

2. **横向滑动不利于「找特定一款」和横向对比**。当前缓解手段是圆点指示器，
   但 11 个圆点无法表达具体位置。若要加强，可考虑加「3 / 11」计数或提供一个紧凑网格入口。

3. **真机待验**（静态检查覆盖不到）：
   - `swiper` 嵌套在 `scroll-view` 内的竖向/横向手势冲突；
   - 拍立得卡在 iPhone SE 等小屏上是否被裁；
   - 展开「香气成分」后雷达是否正常绘制（canvas 在 `v-if` 内，依赖 `drawRadarSoon` 重新测量）。

4. `canvas-draw.js` 仍处于**未提交**状态（上一轮封存卡改动），建议尽快提交。

## 后续：P0 / P1 一致性收口（同日完成）

首轮改版只落地在图鉴「香水」tab，结果是新旧两套规范并存——同一套数据在四个页面有四张脸。本节记录收口过程。

### P0：一致性

| 项 | 改前 | 改后 |
|---|---|---|
| 收藏 / 历史 / 首页首屏 | 8rpx 灰底胶囊 + 纯色填充 | 6rpx **本色细线、无灰底轨道** |
| 工坊六维切换 | 原生 `<switch>` | 两枚文字 pill（与图鉴一致） |
| 共享样式 | 两页 scoped 各写一份 | 提至 App.vue 全局（`.rm-pill` / `.radar-mode` / `--font-hand`） |
| `accordColor` | gallery 有一份本地重复实现（fallback 硬编码） | 收口到 `theme.js` 公共导出 |

**为什么 top3 不照搬图鉴的堆叠色带**：色带语义是「完整香气结构堆叠 100%」，而这三处是 top3 独立项，堆在一起会让人误以为这三项就是全部。改用「本色细线、无轨道」——三条上下并列，靠彼此长短表达主次。

### 修掉的两个真 bug

1. **纯水污染 top3**：`BLEND_KEYS = ACCORDS + SOLVENT`，历史/收藏存的 `accords` 含纯水，纯水重构后「水 80%」会稳占第一，而水既没气味也没颜色（只能 fallback 主绿）。修法：滤掉 `SOLVENT.key` 后**按剩余香调归一到 100**——条宽表达的是香调之间的主次，不是占整瓶的百分比，否则一瓶淡香的三条都只剩一根头发丝。
2. **手记「约 2 分钟」是写死的**：9 篇长短不一却报同一个数。改为按字数实估（400 字/分钟），实测 1~2 分钟；同时去掉「N 段」——内部段落数对读者无意义。

### P1：语言延伸

- 香料 tab：104 个灰药丸 → 标本格，每格底下一条它自己的香调构成色带（气味指纹）。上一轮遗留的「3 种 accords 不求和为 1」在展示层归一后不再是障碍。
- 手记 tab：元数据去参数化（见上）。
- 收藏 / 历史：卡片改拍立得小卡语言（8rpx 小圆角 + 1rpx 细边，不再是 16rpx 大圆角色块），感言用 `var(--font-hand)` 楷体，与封存卡、图鉴拍立得呼应。

### 斜体 → 楷体

**中文没有真正的 italic 字形**：iOS/Android 都是把方块字机械倾斜约 12°，观感是「字歪了」而不是「手写」。英文斜体才是专门设计的字形，中文不是。字体栈本来就写了楷体，问题在于叠了 `italic`——去掉即可，栈提到 App.vue 的 `--font-hand` 三处共用。

### 真机项 ① 已直接修复：swiper circular 与教程高亮冲突

`circular` 会复制首尾节点，教程第 3 步的 `#coachGalleryCard` 可能选中屏幕外的副本，聚光灯画到屏外 → 引导卡死在 3/5。与早前 2/5 的成因不同，`ensureCoachTargetVisible`（切 tab + deckIndex 归零）救不了，审计脚本也查不出。修法 `:circular="!tut.active"`；副作用是教程期间首尾滑到边界会停住。

### 验证

五个审计脚本 + 74 条功能测试全过；构建成功；`console.log` = 0；主包 991K。
产物核对：`--font-hand` 与 `.rm-pill` 各只在 `app.wxss` 出现 1 次，页面级 wxss 无重复定义。

### 新发现但未处理

`generateFormula` 的 `total` 把纯水算进分母，导致「纯水 100% 封存」时配方会返回库序前六香料（幻觉）而非空。与本次 top3 修复同源，建议下一轮一并处理。
