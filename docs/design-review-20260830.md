## 总体判断

体系是有体系的：暖灰纸感（#f0eee5/#f6f3ea）+ 单一主绿（#2e5c45）+ 金重音（#a97826）的三色系统、22/24/26 为主的字阶、克制动效，无 AI 俗套（紫蓝渐变/纯黑/玻璃拟态/斜体均已不存在）。**最需要修的一条是：金色 #a97826 被用作「核心数值」的颜色，但它在纸底上的对比度只有 3.50:1（WCAG AA 要求 4.5:1），而它印的恰恰是滑块百分比、挑战分数这些最需要读清的信息。**

## 设计优势（防止优化时误伤）

- 正文对比度 12.72:1（AAA）、主绿标题 6.93:1、白字绿底按钮 7.68:1、正文灰 4.86:1——主体可读性健康（脚本计算值）
- 中文全站系统字体、全站无斜体、无 `transition: all`、无 `ease-in`——与 qiaomu 反套路禁令全项吻合
- 危险操作全有确认弹窗；错误信息都带下一步动作
- 阴影统一染主绿色调；暖灰纸感一致

## 优先问题

### P1 · 金色数值对比度不足（全站性，已确认）

- **位置**：滑块百分比（24rpx 加粗）、挑战相似度大数字（30rpx 加粗）、封存小字（13px）、模板/入口按钮描边文字
- **现象**：`#a97826` on `#f6f3ea` = 3.50:1、on `#f0eee5` = 3.34:1（脚本计算），低于 AA 4.5:1；且这些数字均不满足「大字号加粗」豁免（需 ≥18.66px bold）
- **影响**：核心数值在强光/低端屏上最先不可读——它们恰是调香与挑战的反馈核心
- **修改**：数值类金色加深为 `#8a5f18`（on #f6f3ea ≈ 5.6:1 ✓，彩蛋标题已在用）；装饰性描边/图标可保留原金
- **验证**：contrast 脚本复跑全部金色组合

### P2 · 四处一致性噪声

1. **辅助灰 `#7a7970` on `#f0eee5` = 3.77:1**——距 AA 差临门一脚，提为 `#6b6a6a`（4.86 ✓）即达标；代价是与引用文本同色，层级改由字号区分
2. **断档预警角标**：白字 on `#b0ae9f` = 2.23:1，几乎不可读（新增功能引入）；底色加深或改红底
3. **字号奇数档**：21/23/25/27/29rpx 共 45 处，与相邻偶数档肉眼无差却破坏节奏——全局收敛到相邻偶数
4. **圆角 12 种取值**（2~30rpx）——收敛到 8/12/16/24 四档

### P2 · 触控目标低于规范（已确认）

rpx→pt 换算（750rpx = 375pt）：步进按钮 44rpx = 22pt、香调 ⓘ 22pt、关闭 × 24pt——低于 WCAG 2.2 的 24pt 最低线，更低于 iOS 44pt 建议。行业现状如此、且有确认弹窗兜底，故定 P2。修法：热区外扩（padding），不做视觉放大。

## 反证检查（通过项）

- 首页居中 Hero：移动端单列惯例 + 情感化工具页定位，属有意策略，非 web 落地页的居中滥用
- 暖灰纸感 + 单主绿 + 金重音：符合「暖色高端」原型，无紫蓝渐变、无纯黑、无过饱和重音
- 阴影统一染主绿色调；三处 eyebrow 未超配额
- 挑战完成弹窗、删除确认、错误带下一步：qiaomu「危险操作不即时执行 / 错误含下一步」两条通过

## pencil 基线对照（选择性采纳）

pencil 的 Inter/白底/8px 网格是另一套体系，**不构成判错标准**（证据优先级：自建体系 > 通用规范）。可借鉴的两点：文本溢出防护（历史行名换行 ✓、入口副标题有省略号 ✓）、状态完整性（空/错/加载态均已覆盖 ✓）。
